Why “palimpsest”

TL;DR. Some invisible Unicode corruptions never reach a neural translation metric: the tokeniser erases them first, so a corrupted translation and a clean one arrive as the same token sequence and receive the same score. We measure that across XLM-R and mT5, build LIGATUR, a 171-item challenge set that separates byte-level corruption from semantic error, and build AEGIS, a metric that scores a cleaned hypothesis and charges the corruption through transparent penalties.

A palimpsest is a manuscript scraped clean and written over, with the old text still faintly there. That is the effect studied here: a translation is corrupted at the byte level (a no-break space for a space, a byte-order mark in front, a zero-width character inside a word), the tokeniser scrapes the corruption off, and the metric reads the surface underneath. A human looking at the string sees nothing; the metric sees nothing; the pipeline downstream sees a perfectly clean sentence.

Where the information disappears

Neural metrics such as COMET-22 and MetricX-24 do not read text; they read token ids. COMET-22 is built on XLM-R and MetricX-24 on mT5, and both tokenisers are SentencePiece models. Before SentencePiece cuts a string into pieces, a normaliser rewrites it, and that rewrite is where the palimpsest effect lives.

The question is empirical: for each kind of invisible corruption, does the token sequence change? The probe answers it for every clean sentence in the challenge set (252 distinct German and Hindi target strings), under both encoders.

The probe: twelve classes, a clean split

For each class the probe applies the perturbation to every applicable sentence and checks tok(clean)["input_ids"] == tok(perturbed)["input_ids"]. A sentence is “applicable” when the perturbation exists for it (space substitution needs a space; intra-word insertions need a word of at least four letters; the homoglyph needs a Latin “o”; the conjunct class needs a virama).

Four classes are erased: a no-break space, a narrow no-break space or an ideographic space substituted for every space, and a byte-order mark at the very start of the string. Eight survive. The result is identical for XLM-R and mT5, which looks like a coincidence until you see that the two tokenisers ship the same normalisation rules.

The mechanism, from the tokenisers’ own config

Both xlm-roberta-large and google/mt5-large are SentencePiece models with a 250,000-piece vocabulary and the same nmt_nfkc normaliser: an identical 237,539-byte precompiled character map, plus remove_extra_whitespaces and add_dummy_prefix. Hugging Face exposes it as a Precompiled normaliser, so you can feed it single characters and read the output. This check is not in the repository; it is three lines to reproduce:

python
from transformers import AutoTokenizer
for name in ("xlm-roberta-large", "google/mt5-large"):
    tok = AutoTokenizer.from_pretrained(name)
    for c in ("\u00a0", "\u202f", "\u3000", "\ufeff", "\u200b", "\u2060", "\u00ad"):
        print(name, f"U+{ord(c):04X}", repr(tok.backend_tokenizer.normalizer.normalize_str("x" + c + "y")))
“Deletes” is accurate, with one nuance

For the four erased classes the corruption genuinely vanishes from the model’s input. Zero-width space, ZWNJ and the directional marks are not deleted but rewritten to a space, so inside a word they split it in two; the ids differ for that reason, and the probe correctly counts them as visible to the model. A few characters (word joiner, soft hyphen, combining grapheme joiner) just survive as odd pieces.

This gives an operational rule: a corruption that is ordinary whitespace in disguise is invisible to these metrics; a corruption that is a different character is visible as a token, even though a human cannot see it. The practical consequence is uneven: the metric can react to a zero-width space but cannot react to a no-break space.

LIGATUR: a challenge set built to separate the two failure modes

A metric that fails on an invisible corruption is not necessarily bad at translation. LIGATUR is built to tell the two apart: the same metric is tested on byte-level corruption (meaning and rendering unchanged), on visible script errors that a competent metric should catch, and on semantic errors that confirm the set does not simply penalise all variation.

Each item is a contrastive pair over one English source: the reference, a correct hypothesis and a minimally corrupted one in randomised slots. The corrupted variants come from deterministic injectors (for the script-form and Unicode phenomena) or are authored as minimal pairs (for the semantic ones). A fixed seed (13) makes the generator reproducible.

On the Devanagari items

The conjunct and joiner items are built to be byte-level correct (a zero-width character inserted after a genuine virama), but how severe a given break looks to a native reader is a separate judgement. The data README recommends native-speaker confirmation before drawing downstream conclusions. The 79 items that differ only by invisible characters (42 en–de, 37 en–hi) are the cleanest test; the rest of the corruption items combine invisible characters with look-alike letters.

Format details follow the official shared-task rules: a set name of at most seven letters (LIGATUR is seven), one language pair per file, <src>.<tgt>.<Name>.jsonl file names, the same number of hypotheses and references per file and a 1,000,000-token cap (the set is about 4.7k whitespace tokens).

AEGIS: score the cleaned text, charge for the corruption

If the neural metrics cannot see invisible corruption, a metric built from them needs another channel. AEGIS makes that channel explicit rather than hoping the encoders notice. Neural metrics score a cleaned hypothesis; a deterministic hygiene shield turns byte-level corruption into a transparent penalty in the same 0–100 points.

Fusion

Three neural signals are blended: COMET-22 and MetricX-24 in reference mode (averaged into an ensemble), and MetricX-24 in reference-free mode as a floor that is always available. How much the blend leans on the reference depends on how much the reference can be trusted.

The trust guard

Synthetic or post-edited references can be bad. AEGIS scores the reference as if it were a hypothesis (MetricX-24 on the reference, empty reference) and compares its error with the median error of the item’s real hypotheses. If the reference is worse by more than 3 error points, the reference weight is halved, so a broken reference cannot drag every hypothesis down with it.

The hygiene shield

code/aegis_shield.py (abridged)
def _clean(text):
    # what the neural metrics are shown
    text = "".join(c for c in text if c not in INVISIBLE and c != SOFT_HYPHEN)
    text = "".join(" " if c in WS_VARIANTS else c for c in text)
    return unicodedata.normalize("NFC", text)

# a penalty only counts characters absent from BOTH trusted texts
trusted = set(src + (ref or ""))
bad = sum(1 for c in hyp if c in INVISIBLE and c not in trusted)
penalty += min(bad * 2.0, 8.0)

What the numbers say

The repository contains one set of published metric numbers: COMET-22’s failures on seven LIGATUR phenomena, stored as constants in the CPU re-computation script so the author’s run can be diffed against them. They line up with the tokeniser probe in the way the hypothesis predicts.

Read left to right, the table is the argument in miniature. COMET-22 does well on everything the tokeniser does not erase (soft hyphens, conjuncts, digit swaps) and fails completely on what it does, with a margin of precisely zero. The one NBSP item that COMET-22 passed is not explained in the repository, so it should not be over-interpreted. Reference-copy is a different failure again: the reference-mirroring candidate is preferred even though it flips the meaning.

The AEGIS submission includes a self-check against LIGATUR: validate_submission.py counts the pairs where the submitted score ranks the corrupted hypothesis at or above the correct one and prints an expected baseline of about 6 failures in 159 pairs. The committed code also contains the scripts for the WMT24 ESA correlation analysis (segment-level Pearson with bootstrap confidence intervals, Kendall τ, pairwise ranking accuracy, a sensitivity grid over w), but the inputs are distributed elsewhere, so those numbers are not reproduced here.

Auditing the shield on the released set

Because the released items nearly always contain the reference as one of the two hypotheses, anyone can run the shield over LIGATUR and see which corruptions it catches.

Where the shield falls short
  • Default-ignorables outside its set. U+E0101 (variation selector 18) is not in the 26-point INVISIBLE list, so ten of the twelve “default-ignorable” items are not penalised. The fix is one line.
  • Small margins. A no-break space costs 0.5 points (cap 2.0). It ranks correctly, but the margin is tiny next to a neural score’s noise.
  • Docstring versus probe. The shield’s docstring says the XLM-R tokeniser strips default-ignorable insertions; the probe shows that only the whitespace-mapped set is truly invisible, and a zero-width space inside a word is visible to COMET-22 (margin 0.107).

What this does and does not show

  • It shows that four classes of invisible corruption are token-identical to clean text on every applicable sentence, under XLM-R and mT5, and that the other eight are not.
  • It shows that for those four classes, an XLM-R-based reference metric has a score margin of exactly zero (COMET-22: BOM and NBSP).
  • It does not show that every neural metric is blind: a metric built on a different tokeniser, or an LLM judge that reads raw characters, behaves differently. The probe covers the two encoders behind COMET and MetricX only.
  • It does not show how often these corruptions occur in real MT output; LIGATUR measures sensitivity, not frequency.
  • LIGATUR is small (171 items, two language pairs), and its Devanagari items are byte-level correct but not yet confirmed by native readers.
Limitations

Only the tokeniser probe is self-contained; the rest of the pipeline needs the official WMT26 test set, WMT24 ESA judgements, the COMET-22 and MetricX-24 checkpoints and GPU time. The gold key is withheld. The CPU variant of the COMET scoring script is marked as not run end to end. The official WMT26 rankings and the paper’s final PDF are not part of the repository.

Reproduce the probe

It runs end to end from the repository alone, needs only the two tokenisers, and finishes in seconds on a CPU.

shell
git clone https://github.com/amethystani/palimpsest && cd palimpsest
uv run --with transformers --with sentencepiece --with protobuf \
    python code/tokenizer_probe_broad.py
# diff the output against the committed results:
#   data/probe_broad_results.json

The repository’s probe_broad_results.json is committed so you can diff your run against it; re-running the probe gives an identical file. The shared-task data lives in wmt-conference/wmt26-mteval. Models: xlm-roberta-large, google/mt5-large, Unbabel/wmt22-comet-da.
