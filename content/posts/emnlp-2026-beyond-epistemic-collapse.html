The failure mode: one fluent answer

TL;DR. Ask a scientific RAG system whether homework improves achievement, whether statins help in primary prevention, or whether a higher minimum wage costs jobs, and you get one confident paragraph, even though the literature is genuinely split. We call that epistemic collapse. EVIRAG keeps the disagreement instead: it retrieves adversarially, builds a signed claim graph, attributes why sources disagree, and answers with source-linked views and an evidence-structured confidence. EVIRAG-BENCH, 1,250 queries across five contested domains, measures whether a system preserved the disagreement.

How to read the numbers

Every result below is “the paper reports”. The public repository ships the full pipeline, the metrics, validators and a 1-query smoke fixture; the 1,250-query gold file, the 989-paper corpus and the raw system outputs are not in it (its FAQ says a full run is tracked as an open issue). The project website shows the same paper numbers. Where I computed something from the paper’s tables (a gap closed, a ratio) it is labelled as derived.

The paper is careful about what this claim is. It is not that every query needs many answers; it is that questions with persistent disagreement need an output interface that preserves viewpoint structure, provenance and uncertainty. Improving retrieval recall alone does not fix it if synthesis still compresses the evidence into one paragraph. “Epistemic collapse” is used as a technical term here and should not be confused with its meaning in modal epistemology.

What counts as collapse

Definition 1 makes the failure behavioural and testable: a system exhibits epistemic collapse on a query with ground-truth view set V* if its answer covers at most one view, ViewpointCoverage ≤ 1 / |V*|. A long single answer that does lay out several views does not collapse under this definition, which is exactly why the paper includes a structured-prompt baseline that does just that.

There is also a mechanism. Topical retrieval tends to oversupply the dominant view, a “consensus attractor”, and a single-vector summarisation objective presses toward it. The homework query shows the difference in practice:

Both answers are fluent and locally accurate. Only one of them tells you the finding depends on grade level, that the effect vanishes once socio-economic status and teacher quality are controlled, and that the outcome you measure (achievement or wellbeing) decides the answer.

EVIRAG: seven stages, one principle

The design principle is that disagreement must be modelled before synthesis: once the evidence is a paragraph, the viewpoint structure cannot be recovered. The pipeline therefore does its structural work first and writes last.

Stage 2: retrieval that argues with itself

A single query retrieves the consensus. EVIRAG runs four role agents with different objectives (Precision, Recall, Skeptic, Counterfactual), each writing its own search query, with a fixed budget of at most 15 chunks. The Skeptic is the only agent whose objective is explicitly anti-consensus.

Stages 3 to 6: a signed graph of claims

Retrieved passages are broken into atomic claims, each carrying a provenance pointer. Every plausible pair is labelled supports, contradicts or neutral, and every contradiction is given a cause. The graph is partitioned with signed Louvain modularity, implemented from scratch in the released Rust; each community becomes one view.

CDA-7: why do they disagree?

NLI tells you that two claims conflict; it does not tell you why. CDA-7 adds that dimension, with seven causes, one primary cause stored on each contradiction edge.

Stage 7: confidence from evidence, not fluency

Each view gets a confidence tier. The class of the controversy (below) scales how confident a view can be, so a polarized topic is never presented with the confidence of a settled one, however well the prose is written.

Confidence is robust to labelling noise

Perturbing every contradiction’s CDA-7 label to its most confusable neighbour (methodological ↔ population, statistical ↔ methodological) leaves the confidence tier unchanged on 88.4% of queries; movers shift by one tier and none go from high to low.

EVIRAG-BENCH: measuring what systems erase

Standard retrieval metrics reward topical relevance to a single answer. EVIRAG-BENCH measures epistemic fidelity: how much of the structured disagreement in a literature a response preserves. The corpus is 989 papers across five domains with persistent, well-documented controversy.

  1. Freeze the corpusSave each paper’s DOI, title, year, venue, access date and licence; mark full text versus abstract.
  2. Draft questions independently of system outputs250 per domain; record the source papers behind each.
  3. Annotate viewpointsTwo annotators independently identify 2–4 positions, each with a proposition and a passage ID, distinguished by conclusion, population, definition or theory.
  4. Record contradiction pairs1–8 pairs of incompatible atomic claims per query, each labelled with a CDA-7 cause. Compatible claims are not contradictions.
  5. Assign a controversy classAfter inspecting the evidence over time, with a written rationale.
  6. Adjudicate and freeze before any system runsKeep both independent files, the adjudicated file, notes, annotator IDs and a checksum of the frozen JSONL.

The paper reports Cohen’s κ = 0.71 for viewpoint identity and κ = 0.68 for CDA-7 conflict types on a 200-query re-annotation by an external consultant. The gold file was version-locked before any system was run, and every system was scored against it unchanged. The annotation was done by the authors with one external domain consultant per domain.

The validator enforces the shape

validate-gold checks unique ids, one of five domains, 2–4 viewpoints each with sources, 1–8 contradictions with a valid CDA-7 label, and a valid controversy class. With --full it also insists on exactly 1,250 queries, 250 per domain, and class counts of 190 / 335 / 445 / 280, so a malformed full release cannot slip through.

The metrics, and the one the paper threw away

Because SVC depends on which gold view each claim is nearest to (an argmax) rather than on the size of a cosine, it is invariant to the inflation of absolute cosines that encoder anisotropy induces. That makes it a better collapse measure than anything that averages similarities.

A metric audit, and a negative result

A metric can be plausible, publishable and still measure the opposite of its intent. The paper audits its own suite for direction validity: on instances where the right ordering is known independently of the metric, does the metric agree?

Why this matters

The suite was designed by the same team as the system, which the paper calls the most serious threat to its results. Auditing the metrics against known orderings, and reporting that the first headline metric failed, is evidence that the evaluation was checked rather than assumed. The keyword variant of ViewpointCoverage was demoted for a related reason: it saturates between 0.892 and 0.991 across every system, so a 1998 retrieval heuristic (MMR) and a seven-stage pipeline differ by 0.007.

Results

Which part earns its keep?

Dropping multi-view output costs the most; dropping the retrieval ensemble or the claim graph costs less but still hurts. Note what the NoGraph row says: with the same evidence and the same multi-view format but no graph, contradiction recall reaches only 0.604, below the structured prompt’s 0.613. What the graph buys is contradiction structure, not output shape.

Controls: is it just more compute?

EVIRAG makes about 14 calls where baselines make one, so a skeptic can say the gains are just more inference. The paper adds three controls: a closed-book run, a budget-matched run that retrieves 15 chunks like EVIRAG, and a single call with a structured prompt that asks for every viewpoint, its evidence, its weaknesses and why the sources disagree.

Where it breaks

The paper’s own list of limits is long and specific, and worth reading as the other half of the result:

  • Benchmark circularity. The benchmark, the metrics and the system share authorship. The paper’s defences are the cross-system ordering (the structured prompt, which shares none of EVIRAG’s components, beats the NoGraph ablation on coverage), the version-locked gold with external consultants, and metrics adapted from SciFact, ExpertQA and FActScore. It then says it does not claim neutrality: the decisive test is a disagreement-aware system built by another group, evaluated on EVIRAG-BENCH by that group.
  • Compute is not fully matched. The clean test, a call- and token-matched version of EVIRAG’s own strategy, has not been run. The paper states its prediction in advance and says it would report a failure.
  • Louvain’s resolution limit. A small enough minority view can be absorbed into a larger community rather than surfaced as its own view, understating coverage exactly where minority positions are rarest.
  • Publication bias. Null and negative results are underrepresented in academic corpora; the Skeptic cannot recover evidence that was never published.
  • Scope. Five contested domains; not evidence that the gains transfer to settled factual QA or to arbitrary web RAG. On settled queries the system can produce unnecessary multi-view output, and the intent gate is imperfect: false positives give mild over-complexity, false negatives give collapse.
  • Model dependence. One open-weight backbone for the main results; prompt-based NLI remains the major source of error; temporal drift is not ablated.
Ethics: do not mistake dissent for equal credibility

Surfacing minority views risks cherry-picking and, in health domains such as statins, harm if read as medical advice. EVIRAG outputs are designed for research synthesis, not clinical decisions, and source counts, causal attribution and confidence labels are part of the output surface precisely so that minority claims are not treated as equally credible. Extending the idea to journalism, policy or legal settings needs evidential weighting that EVIRAG does not model, and the paper flags that as future work rather than a property of the present system.

Reading the released code against the paper

The repository is a Rust re-implementation released with the camera-ready. It is a faithful skeleton of the pipeline, and in a few places simpler than the prose. For anyone reproducing it, these are the differences worth knowing:

A real saved run, and what it is

The repository includes a saved smoke run: one query (“Does homework improve academic achievement?”) over two synthetic passages with a 0.5B model. It produced three views, eight claims and nine edges (six contradictions, all labelled methodological, and three supports). It exists to prove the pipeline wires together end to end, not to show quality, and the project site says as much.

Run it

Rust, Ollama and a chat and an embedding model are all it needs. The smoke script exercises every command on the fixture; the full commands take your own corpus and gold file in the formats above.

shell
git clone https://github.com/amethystani/evirag-bench && cd evirag-bench
cargo build --release
./scripts/smoke.sh                      # chunk, index, run, validate-gold, evaluate on a 1-query fixture
ollama serve                            # scripts/fetch_models.sh pulls qwen3.6:35b-a3b and all-minilm

target/release/evirag-bench validate-gold data/gold/pilot.jsonl          # add --full for the 1,250-query layout
target/release/evirag-bench chunk data/corpus/documents.jsonl data/corpus/chunks.jsonl
target/release/evirag-bench index data/corpus/chunks.jsonl data/index.json
target/release/evirag-bench run data/index.json data/gold/benchmark.jsonl runs/full.jsonl --system full
target/release/evirag-bench evaluate runs/full.jsonl data/gold/benchmark.jsonl runs/full.metrics.json
scripts/run_all.sh                      # every system, then paired comparisons

Every LLM call goes through Ollama’s /api/generate with temperature 0 and a 256-token cap, and embeddings are L2-normalised in code. The test suite (cargo test) covers the chunker’s exact overlap, three signed-Louvain cases (two camps are recovered exactly), the typology boundaries, the bootstrap and an exact Wilcoxon test, and needs no model. CI runs formatting, tests and clippy with warnings denied on Linux and macOS.
